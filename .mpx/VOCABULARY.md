# Grovekeeper Vocabulary

Canonical terms used across codebase, UI, docs, and conversation. Update this whenever a new concept emerges.

---

| Term                  | Definition                                                                                                                                                                                                                                                                                                 |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Workspace**         | Top-level container binding one GitHub repo + one project folder + one dashboard. Each Grovekeeper window displays one workspace. Configurable worktree folder, default provider, and base branch.                                                                                                         |
| **Overview**          | The multi-workspace launcher view. Shows all configured workspaces as cards with health indicators. Opened on startup (configurable) or when no workspace is focused.                                                                                                                                      |
| **Issue**             | The atomic unit of work. Linked to one GitHub issue, one worktree, one branch. Has a color and status badges. Can have many sessions over its lifetime. Priority exists but defaults to medium and is not prominently displayed unless the user explicitly changes it.                                     |
| **Session**           | One AI agent CLI execution (Claude Code, Cursor, Codex, etc.) tied to an issue. Has a transcript, tool calls, cost, turns, and a state (running/needs-input/finished/errored). Multiple sessions can exist per issue.                                                                                      |
| **Provider**          | An AI agent CLI backend (Claude Code, Cursor, Codex, OpenCode, etc.). Each session runs on one provider. Providers expose capabilities: spawn, discover, import history.                                                                                                                                   |
| **Issue Environment** | The per-issue bundle of external tools: worktree folder, editor instance, terminal session. Not called "workspace" (that term is reserved for the top-level container).                                                                                                                                    |
| **Worktree**          | A git worktree checked out for an issue's branch. Created via `setup-worktree.sh`. One-to-one with an issue. Stored in per-project sibling folder (`{parent}/{name}-worktrees/`).                                                                                                                          |
| **Forest**            | The visual metaphor for issue state. Each tree represents an issue at its lifecycle stage. PRD tree at center, blocking relationships shown as depth rows. Default landing page.                                                                                                                           |
| **Tree Stage**        | Lifecycle stages mapping issue state to tree appearance: seed, sprouting, sapling, growing, leafy, flowering, fruiting, seasonal, wilting, bare, dead, stump. Botanical order: flowering (PR open) before fruiting (PR approved). See `.mpx/STATE_MAPPING.md` for the priority-ordered cascade rules.      |
| **Badge**             | A color-coded status indicator on an issue card. Types: branch status, PR state, GitHub issue state, sync/behind-base, merge conflict. Responsive — compacts to icon-only when space constrained.                                                                                                          |
| **Skill**             | A named Claude Code slash command (e.g., `/mp-execute`, `/mp-review`). Represented as a clickable button in the UI and browsable in AI Configuration.                                                                                                                                                      |
| **AFK**               | GitHub issue label indicating autonomous execution readiness. The AFK monitoring loop picks up AFK-labeled issues and spawns execution sessions automatically.                                                                                                                                             |
| **HITL**              | Human-In-The-Loop. GitHub issue label indicating questions need user resolution before execution. One-way flip to AFK after resolution. Never flips back — unresolved items from execution create new linked issues.                                                                                       |
| **CESP**              | Common Event Sound Protocol. Sound pack manifest format (from peon-ping project) used for notification sound packs in Grovekeeper.                                                                                                                                                                         |
| **Deep Module**       | Architecture pattern from Ousterhout's "A Philosophy of Software Design." Small interface hiding large implementation. Each frontend module exposes a `use{Feature}()` context factory.                                                                                                                    |
| **Priority**          | Issue importance level (lowest/low/medium/high/highest). Defaults to medium, not prompted during issue creation. Medium has no badge; non-default levels show a badge on the card. Users can change priority via issue card action. Blocking relationship display and some views sort by priority.         |
| **Design Token**      | A named CSS custom property (OKLCH colors, typography, spacing, shadows, motion, z-index) defined in `app.css` under `@theme inline`. Semantic tokens (e.g., `--surface`, `--foreground`) swap values between dark/light themes via `[data-theme]` selectors. Source of truth: `claude_design/tokens.css`. |
| **Accent Color**      | One of four color themes (moss, amber, bark, azure) applied via `data-accent` attribute on `<html>`. Overrides `--primary`, `--primary-fg`, `--primary-soft`, and `--ring` CSS custom properties at runtime. Moss is the default.                                                                          |
| **Command Palette**   | Global `Ctrl+K` overlay that searches across actions, navigation routes, and issues with fuzzy matching. Consumes the action registry — any action registered via `useActions()` auto-appears. Groups results by category (Actions, Navigation, Issues).                                                   |
| **Shortcut Registry** | Reactive Svelte 5 context (`useKeyboardShortcuts()`) where actions register with default key bindings. A `window` keydown listener dispatches matched bindings. Custom bindings are persisted in SQLite and editable inline in the Settings panel.                                                         |
| **Action Registry**   | Module (`useActions()`) that maintains a list of executable actions (skills, navigation, utilities). Actions auto-appear in the command palette and can display their bound keyboard shortcut.                                                                                                             |
| **Execution Phase**   | The current step within an active agent session, derived from stream-JSON parsing. Phases: `analyzing`, `tdd`, `reviewing`, `testing`, `fixing`, `shipping`. Each phase maps to a specific tool accessory on the tree (lantern, shovel, pruningShears, rake). See `.mpx/STATE_MAPPING.md`.                 |
| **Sub-Agent Bird**    | Visual representation of a sub-agent spawned during execution. Birds appear in the tree canopy at branchTips. Six types: owl (analyzer), robin (executor), sparrow (checker), cardinal (reviewer), hummingbird (utility), parrot (research). Multiple of same type for parallel agents. Fade on finish.    |
| **Glow Overlay**      | SVG feGaussianBlur-based glow around a tree. Priority-ordered: hover (yellow) > selected (blue) > errored (red pulse) > needs-input (orange pulse) > ready-to-merge (green, intensity 5) > approved (green, intensity 2). All colors configurable in settings.                                             |
| **State Mapping**     | The priority-ordered rule table that determines which tree stage, accessories, overlays, glow, and animations to display for a given combination of issue state dimensions. Canonical reference: `.mpx/STATE_MAPPING.md`.                                                                                  |
